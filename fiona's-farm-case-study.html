Fiona's Farm: growing a storefront from the groundup

A single-page, mobile-first storefront for Fiona's Farm, a fresh produce business bringing its fruit and vegetable catalog online for the first time. Built solo in semantic HTML and CSS, matched to the farm's own green and orange brand system.

The Brief

Fiona's Farm had a loyal following at the farmers market but no web presence. There was no way for people to see what was in season, check hours, or find the farm's location before making the trip. The goal was one storefront page that felt trustworthy and homegrown, listing every fruit and vegetable the farm sells alongside hours and contact details.

Irish Grover headings give the page a hand-lettered, market sign feel. Habibi handles the body copy so it stays warm without getting hard to read. Green and orange show up in the nav, the category tags, and the footer, so the page reads as one connected brand instead of separate sections.

Layout was built mobile-first across four breakpoints, 428, 834, 1280, and 1440px. Someone checking hours from their phone should get the same experience as someone browsing on a desktop.

03

Building the Storefront

Foundation

I started with a CSS reset so I was not fighting default browser styles later, then set up root variables for the two brand colors and the type sizes immediately. That way, if the client wanted a shade of green tweaked down the road, it is a one-line change instead of hunting through the whole stylesheet.

Semantic Structure

Every part of the page uses actual HTML5 tags, <header>, <nav>, <main>, <section>,<article>,<footer>, instead of a pile of generic <div>'s. I ran the code through the HTML validator and fixed everything it flagged. For a small business that depends on people finding the website, it matters more than it sounds like it should.

Mobile-First, Then Scaling Up

The 20-item produce catalog stacks in a single column on phones. As the screen grows through each @media screen and (min-width: …) breakpoint, the grid opens up into more columns, so the full catalog gets room to breathe on desktop without cramming everything on the phone screen.

04

Problems I Ran Into

Positioning Instead of Real Layout

I built the first pass of a few sections with manual positioning, nudging things into place with margins and offsets instead of using flex or grids. It looked fine until I dropped real content into it and the layout started breaking at the medium and large breakpoints. I ended up tearing those sections back out and rebuilding them with proper flex containers so the spacing would hold up no matter what the content looked like.

Breakpoints Drifting Apart

Once I had four separate media queries going, keeping them consistent got harder than I expected. I fixed a spacing issue at 834px and forgot to check whether the same fix needed to happen at 1280px, so things would look right at one size and slightly off at another. Root variables helped, but I still had to go back through all four breakpoints more than once to find bugs I missed.

Grid Alignment on the Product Cards

Lining up 20 product cards into a clean grid that did not leave uneven rows took more trial and error than I expected, especially once the column count changed at each breakpoint. A few early attempts left orphaned cards sitting alone in a row by themselves, which meant rethinking how many columns made sense at each screen size instead of just picking a number that looked good on my computer.

05

What I'd Sharpen Next

The biggest thing I would do differently is start with flexbox or grid from the first line of CSS instead of reaching for manual positioning when something needs to move a few pixels. It is faster in the moment, but it makes the whole layout fragile the second real content changes size.

i would also build out the mobile-first plan more before writing any CSS at all, sketching out what changes at each breakpoint ahead of time instead of discovering it live while I am coding.

A few other things I would add if I revisited this project: a search or filter bar for the produce catalog so it is not just a long scroll, some kind of client-side form for special orders or contact requests instead of a static phone number, and a real accessibility pass with a screen reader instead of just running the validator and calling it done.
